# 研究问题清单

更新：2026-10-13。以下均为候选假设，尚无本仓库实验结果支持。

| 候选问题 | 已有背景 | 下一步验证 | 放弃或收窄条件 |
|---|---|---|---|
| 多模态阶段干扰是否导致某类请求持续违反 SLO？ | [ModServe](https://arxiv.org/abs/2502.00937)、[EPD](https://arxiv.org/abs/2501.05460) 已研究阶段差异 | 分解 encode/prefill/decode 的执行和排队时间；比较多种图文混合负载 | 强基线的已有配置可以消除主要问题 |
| token 数是否足以代表请求成本？ | [TCM-Serve](https://arxiv.org/abs/2603.26498) 已研究模态感知调度 | 在相近 token 长度下改变模态和分辨率，测阶段成本 | 额外特征不能改善决策或开销超过收益 |
| 长度预测对调度有多大实际价值？ | [S³](https://arxiv.org/abs/2306.06000)、[FastServe](https://arxiv.org/abs/2305.05920) 提供不同思路 | 先做 oracle 上限，再加入误差与预测开销 | 完美信息相对强基线仍只有很小收益 |
| 视觉预算能否与在线系统状态联合决策？ | 旧构想尚待系统查重 | 对比最好固定策略、仅语义策略、仅系统策略；同时测质量和 SLO | 质量下降不可控，或联合决策不优于分开优化 |
| 分页 KV 的布局是否是目标负载中的主要开销？ | [FlashInfer](https://arxiv.org/abs/2501.01005)、[vAttention](https://arxiv.org/abs/2405.04437) 已有不同实现路线 | 在统一模型、硬件和后端下测 kernel、索引、显存与迁移成本 | 时间主要耗在别的阶段，或收益只来自旧实现缺陷 |

## 实验前需要补的条件

确定一个目标模型及版本、一类请求分布、明确的 TTFT/ITL 或 TPOT SLO。增加图片数和分辨率时，同时检查输出质量，不把更快但答错的响应直接计入有效收益。

“更少 token 一定更快”“相同长度才能 batch”“decode 永远 memory-bound”都不作为先验事实。先确认具体执行路径，再建立可反驳的假设。
